# Оплата через Яндекс Пэй (со Сплитом)

## Как это будет для клиента
1. Клиент выбирает документы или комплекс и жмёт «Оплатить».
2. Сайт сам создаёт заказ в Яндекс Пэй: сумма считается из корзины, назначение вида «Документы по делу ст. 12.27 КоАП: …», номер заказа.
3. Клиента сразу перекидывает на страницу оплаты Яндекс Пэй. Там можно оплатить картой, через СБП или Сплитом (частями).
4. После оплаты он возвращается на сайт. Документы открываются только когда Яндекс подтвердит, что деньги пришли, и сразу попадают в «Мои документы».
5. Если оплата не прошла или клиент закрыл страницу, документы не открываются, заказ можно оплатить заново.

## Что нужно от вас
- **API-ключ мерчанта** из личного кабинета Яндекс Пэй (console.pay.yandex.ru → раздел API / «Ключи»). Я попрошу вставить его в защищённое поле, в код он не попадёт.
- **Merchant ID** (там же).
- В кабинете Яндекс Пэй указать адрес для уведомлений об оплате, я дам точную ссылку после настройки.
- Сначала подключим **тестовый режим** (песочница Яндекса), проверим, потом переключим на боевой.

## Что меняется на сайте
- Убираем демо-оплату: кнопка «Оплатить» ведёт в Яндекс Пэй.
- Экран «Проверяем оплату…» после возврата, затем экран «Ваши документы готовы».
- Цены остаются те же, берутся с сервера, клиент не может их подменить.

## Технические детали
- Таблица `orders` (id, user_id, mode, stage, docs, amount, status pending/paid/failed, yandex_order_id, created_at) с RLS: пользователь видит только свои.
- Серверная функция `createPayment` (requireSupabaseAuth): пересчитывает сумму по каталогу на сервере, создаёт запись orders, вызывает `POST https://pay.yandex.ru/api/merchant/v1/orders` (sandbox: `sandbox.pay.yandex.ru`) с `Authorization: Api-Key …`, cart с позициями, `redirectUrls` (onSuccess/onError на сайт), возвращает `paymentUrl`.
- Публичный маршрут `src/routes/api/public/yandex-pay-webhook.ts`: принимает уведомление, проверяет JWT-подпись по публичным ключам Яндекса, дополнительно перепроверяет статус заказа через API, ставит orders.status=paid и добавляет покупку в cabinets (через admin-клиент только после проверки).
- Возврат на сайт `?order=…`: опрос статуса заказа до paid, затем показ PaidStep.
- Секреты: `YANDEX_PAY_API_KEY`, `YANDEX_PAY_MERCHANT_ID`, `YANDEX_PAY_ENV` (sandbox/live).
- Тест: сумма заказа на сервере равна цене из каталога (комплекс по стадии, корзина).
