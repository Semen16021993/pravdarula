# Контролируемая публикация интерфейса

## Текущий режим

Lovable Preview открывает демонстрационный кабинет без серверной авторизации. Проверка адреса выполняется в браузере после загрузки: только Preview нашего проекта и локальный просмотр. На `pravdarula.ru`, `www.pravdarula.ru` и опубликованном адресе Lovable демонстрационный режим выключен. Параметры URL и `NODE_ENV` не включают его.

Анкета и демонстрационные покупки хранятся только в отдельном локальном кеше Preview. Серверные сессии не создаются, запросы к `/api/*` для входа, кабинета и платежей не выполняются. Кнопка открытия демо-документов не создаёт настоящий заказ.

## Существующая публикация

Изменения исходников Lovable попадают в подключённый GitHub через синхронизацию проекта. Это само по себе не публикует сайт Yandex Cloud. Наличие автоматического развёртывания в настройках GitHub нужно проверять отдельно.

Текущий `deploy-yandex.sh` не предназначен для публикации только интерфейса: он подтягивает `main`, загружает статику, создаёт новую версию Cloud Function и обновляет API Gateway. В этой задаче скрипт не изменён и не запускался.

## Предлагаемый механизм следующего этапа

1. Проверять изменения в GitHub до развёртывания и выбирать конкретный проверенный commit, а не автоматически подтягивать последнюю `main` перед публикацией.
2. Создать отдельный вручную запускаемый процесс **frontend-only** с подтверждением через GitHub Environment. Он собирает статический интерфейс и загружает только файлы Object Storage; не содержит команд обновления Cloud Functions, API Gateway, YDB, DNS, секретов и платежных настроек.
3. Сравнивать выбранный commit с предыдущим опубликованным commit. Отклонять интерфейсную публикацию при изменениях `yandex-api/**`, `deploy-yandex.sh`, конфигурации Yandex, интеграций, `src/lib/cabinet.ts`, `src/lib/payments.functions.ts`, файлов миграций и зависимостей. Изменения общих бизнес-правил, цен, каталога и генерации документов требуют отдельного рассмотрения.
4. Разрешать только согласованный список файлов интерфейса: компоненты, стили, изображения, публичная страница и изолированные модули Preview. Даже изменения этих файлов просматриваются на предмет сетевых вызовов, авторизации и платёжного поведения.
5. Перед загрузкой запускать тесты исключения боевых доменов из демо-режима и проверку интерфейса с заблокированными запросами к API. Проверять боевую страницу входа на собранной статике, открытой с production-адресом в тестовом браузере.
6. Использовать отдельные права только на публикацию статики в нужный bucket. Сохранять предыдущий набор статики и идентификатор опубликованного commit для отката интерфейса без обновления сервера.

Этот процесс пока **предложен, но не подключён**: требует согласования публикационного процесса и доступа GitHub к Object Storage. Текущий production не изменён.
