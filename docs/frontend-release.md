# Единый деплой «Правды Руля»

Lovable → GitHub → Mac → Yandex Cloud. Отдельных frontend-only/backend-only команд нет.

После изменений в Lovable дождаться синхронизации с GitHub и выполнить одну команду:

```bash
cd ~/Desktop/pravdarula && ./deploy-yandex.sh
```

Скрипт сам забирает `main`, устанавливает зависимости, запускает тесты, собирает интерфейс и Yandex API, проверяет текущую конфигурацию, сохраняет резервную копию, публикует затронутые компоненты и проверяет production health/auth. Если проверка после публикации не проходит, скрипт в том же запуске автоматически возвращает предыдущие файлы, API-версию и Gateway.

Изменения общего кода, импортируемого API, попадают и в сборку API. Изменения `yandex-api/` обновляют Cloud Function и Gateway. Новые YDB-миграции автоматически применяются только если они проходят встроенную проверку безопасного additive DDL; destructive/неподдерживаемые миграции остановят релиз до изменения базы.

Production остаётся на Yandex Cloud: авторизация, сессии, кабинеты, заказы и Яндекс Pay Sandbox продолжают использовать существующие Yandex Function, Gateway, YDB и Lockbox. Секреты не копируются из Lovable и не попадают в frontend bundle.

Резервные копии и журнал релизов хранятся локально вне Git в `~/.cache/pravdarula-releases/`. При аварийном завершении следующая команда сначала восстановит незавершённый релиз.

Новые TanStack server functions/API routes, не реализованные в Yandex handler/Gateway, намеренно не маскируются под статические файлы: релиз остановится с конкретным сообщением, чтобы не опубликовать неработающую функцию.

Если после успешной публикации заметил визуальную или функциональную проблему, вернуть предыдущий сохранённый релиз можно отдельной командой (без повторной сборки и Git pull):

```bash
cd ~/Desktop/pravdarula && ./deploy-yandex.sh --rollback
```
